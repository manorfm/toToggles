Executar com Docker

A imagem inclui o servidor, a interface administrativa e as migrations. O banco SQLite é criado no primeiro início dentro do volume persistente.

Imagem estável Use manorfm/totoggle:latest para receber a última release estável. Cada release também mantém sua tag de versão para implantações fixadas.

Última release do servidor latest

1
Inicie o serviço

O Docker cria o volume nomeado quando ele ainda não existe.

2
Acesse a interface

A interface fica disponível em http://localhost:3056.

Terminal
docker run --detach \
  --name totoggle \
  --restart unless-stopped \
  --publish 3056:3056 \
  --volume totoggle-data:/app/data \
  --env COOKIE_SECURE=false \
  manorfm/totoggle:latest

Persistência em um diretório do host

Para guardar os dados em um caminho conhecido do host, monte esse diretório em /app/data. O processo do container usa o identificador 65532 e precisa poder escrever nesse caminho.

Terminal
sudo install -d -m 700 -o 65532 -g 65532 /srv/totoggle
docker run --detach \
  --name totoggle \
  --publish 3056:3056 \
  --volume /srv/totoggle:/app/data \
  --env COOKIE_SECURE=false \
  manorfm/totoggle:latest

Configuração do servidor

Configure o processo com variáveis de ambiente no comando Docker ou no seu orquestrador. DB_PATH deve permanecer dentro de um volume persistente.

VariávelPadrãoUso
SERVER_PORT3056Porta HTTP ou HTTPS do servidor
DB_PATH/app/data/toggles.dbCaminho do arquivo SQLite
COOKIE_SECUREtrueExige HTTPS no cookie de sessão. Use false somente para HTTP local
GIN_MODEreleaseA imagem usa release para reduzir os logs do framework
TLS_CERT_FILEvazioCaminho do certificado quando o próprio servidor termina TLS
TLS_KEY_FILEvazioCaminho da chave privada. Configure junto com o certificado

HTTPS no servidor

Em produção use um proxy reverso com TLS ou forneça certificado e chave ao container. As duas variáveis TLS devem ser configuradas juntas.

Terminal
docker run --detach \
  --name totoggle \
  --publish 3056:3056 \
  --volume totoggle-data:/app/data \
  --volume /srv/totoggle/tls:/tls:ro \
  --env COOKIE_SECURE=true \
  --env TLS_CERT_FILE=/tls/cert.pem \
  --env TLS_KEY_FILE=/tls/key.pem \
  manorfm/totoggle:latest

Primeiro acesso

No primeiro início o toToggle cria o usuário root, gera uma senha temporária e grava o valor no volume de dados. Entre em http://localhost:3056/login e altere a senha quando solicitado.

Terminal
docker run --rm \
  --volume totoggle-data:/app/data \
  alpine:3.22 cat /app/data/initial-root-password.txt
Proteja a senha inicial O arquivo é removido automaticamente depois da troca de senha. Não compartilhe o volume de dados nem registre o conteúdo da senha nos logs.

Modelo de acesso

As equipes são o ponto de ligação entre pessoas e aplicações. Crie a estrutura abaixo antes de integrar uma biblioteca cliente.

1Equipe

Reúne as pessoas responsáveis por um domínio ou produto.

2Aplicação

Pertence a uma equipe e contém os toggles e as chaves de serviço.

3Biblioteca cliente

Usa a chave da aplicação para buscar e avaliar os toggles.

Root

Administra equipes, permissões, usuários, configuração de aprovações e todo o histórico.

Admin

Cria e altera dados nas aplicações às quais possui permissão. Pode criar usuários apenas nas próprias equipes.

User

Consulta os dados liberados para suas equipes e pode propor alterações de toggle.

Aplicações e toggles

Uma aplicação representa o serviço ou produto que consumirá feature flags. Ao criar uma aplicação, escolha a equipe proprietária. Ela recebe permissão administrativa automaticamente.

1
Crie ou escolha uma equipe

A equipe deve existir antes da aplicação.

2
Abra Applications e crie a aplicação

Informe o nome e selecione a equipe responsável.

3
Crie os toggles

Use nomes hierárquicos como checkout.payments.card. Desativar um pai também desativa os descendentes.

O root pode conectar a mesma aplicação a outras equipes e definir acesso read, write ou admin. Leitura permite consultar, escrita permite alterar e administração permite controle completo dentro da aplicação.

Equipes e usuários

O root administra a estrutura de equipes. Em Teams, crie a equipe, inclua os membros e associe as aplicações que ela deve administrar.

1
Crie a equipe

Use um nome que represente a responsabilidade de produto ou domínio.

2
Crie o usuário

Informe nome, login, função e uma equipe. A senha temporária é exibida uma única vez e a troca é obrigatória no primeiro login.

3
Associe aplicações e permissões

Defina quais aplicações cada equipe pode ler, editar ou administrar.

Escopo dos admins Um admin só pode criar usuários em equipes das quais participa. O root pode editar e remover usuários, equipes e seus vínculos em qualquer escopo.

Aprovações e aprovadores

O fluxo de aprovação é opcional e começa desabilitado. Ele permite que alterações sensíveis aguardem uma revisão antes de entrar em vigor.

1
Abra Approval settings como root

Ative o fluxo e escolha as ações que exigem aprovação. A expiração padrão pode ser configurada entre um e trinta dias.

2
Defina os aprovadores da equipe

Em Teams, marque um membro admin ou root como approver. Somente o root altera essa designação.

3
Revise e execute

O aprovador da equipe ou o root aprova ou rejeita a solicitação. A alteração só é aplicada depois da aprovação e da execução.

O root pode exigir aprovação para criação, alteração e exclusão de aplicações, mudanças de toggle, regras de ativação e criação ou revogação de chaves. Usuários membros de uma equipe podem propor uma mudança de toggle mesmo sem permissão de escrita.

Equipe sem aprovador Se o fluxo estiver ativo e a equipe não tiver aprovador, as solicitações dessa equipe não terão quem as revise. Defina ao menos um aprovador antes de exigir aprovação para ações críticas.

Chaves de acesso

Cada biblioteca cliente usa uma chave secreta vinculada a uma aplicação. Admins e root geram a chave na página da aplicação. Dê um nome que permita identificar o consumidor, como produção do checkout.

1
Abra a aplicação

Acesse a seção de chaves e gere uma nova chave para o serviço consumidor.

2
Copie e armazene o valor

O texto da chave é mostrado apenas no momento da criação. Guarde-o em um gerenciador de segredos.

3
Entregue pelo ambiente

Configure o serviço consumidor com TOTOGGLE_SECRET_KEY. Nunca coloque uma chave em código de navegador ou no repositório.

Uma nova chave se torna a chave atual. A anterior continua válida durante a janela de transição e é revogada quando uma rotação posterior a substitui. Quando a criação de chaves exige aprovação, a chave permanece inativa até a solicitação ser aprovada e executada.

Bibliotecas clientes

As bibliotecas usam o nome da aplicação, a URL do servidor e a chave secreta. Elas buscam o catálogo e avaliam os toggles localmente.

Java

Adicione a dependência e forneça a URL e a chave pelo ambiente da sua aplicação.

Gradle
implementation("io.github.manorfm:totoggle_java:1.0.0")
Maven POM
<dependency>
  <groupId>io.github.manorfm</groupId>
  <artifactId>totoggle_java</artifactId>
  <version>1.0.0</version>
</dependency>
Java
ToToggleConfig config = ToToggleConfig.Companion.builder()
    .applicationName("checkout")
    .serverUrl(System.getenv("TOTOGGLE_URL"))
    .secretKey(System.getenv("TOTOGGLE_SECRET_KEY"))
    .build();

ToToggleClient client = new ToToggleClient(
    config,
    ToToggleClientRuntime.Companion.production("checkout")
);
client.start();
boolean enabled = client.isActive("checkout.payments.card");

Go

Terminal
go get github.com/manorfm/toToggles/totoggle_go
Go
config, err := totoggle.NewConfig(
    "checkout",
    os.Getenv("TOTOGGLE_URL"),
    os.Getenv("TOTOGGLE_SECRET_KEY"),
)
if err != nil { log.Fatal(err) }

client := totoggle.New(config)
if err := client.Start(context.Background()); err != nil { log.Fatal(err) }
defer client.Shutdown()

enabled := client.IsActive("checkout.payments.card")

Node

Terminal
npm install totoggle-node
Node
import { createConfig, ToToggleClient } from "totoggle-node";

const config = createConfig(
  "checkout",
  process.env.TOTOGGLE_URL ?? "",
  process.env.TOTOGGLE_SECRET_KEY ?? "",
);

const client = new ToToggleClient(config);
await client.start();
const enabled = client.isActive("checkout.payments.card");
client.shutdown();
